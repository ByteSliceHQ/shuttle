'@swirls/shuttle': minor

Typing `@` in the message box opens a menu of what the message can point at: team members to hand it to, the workspace's other sessions, and the files in the session's repositories. Files are read once from the new `sandbox.paths` route (`GET /sessions/{id}/sandbox/paths`) and searched in the browser as you type. `sessions.say` takes `references`, and the session records them on `shuttle.user.said`: a file by its worktree path, a session with a short digest the Worker reads when the message is sent. Agents get both listed under the message. Mentions are highlighted in the message box as they are picked, and in the conversation, where a file opens in the artifacts pane and a session links to it. `OpenArtifact` accepts `'file'` with a worktree path. A session reference can carry a `label`, the text it is written as: two sessions with the same title are written `@title` and `@title (2)`, so each mention links to its own session. Sessions in the menu show their folder and how recently they changed. A message's mentions survive copy and paste: each message has a Copy button, copying from the message box keeps the mentions in the selection, and pasting either into the message box brings the mentions back as picks. `sandbox.paths` takes and returns an `etag`, so a list that has not changed is not sent again; the menu reads it again only when the session's event log shows something that may have made, deleted or moved files, and adds files agents write in place. Sessions in the menu are ordered by how well they match.

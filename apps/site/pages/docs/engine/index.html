@swirls/shuttle/engine

Host the engine

The engine is what runs Shuttle's sessions: the agents, their sandboxes, pull requests and review. It is a library your Cloudflare Worker hosts. You say who is asking, who pays and how to reach GitHub; it does the rest, and serves the API the parts talk to.

Install

bun add @swirls/shuttle ai @cloudflare/sandbox @daytona/sdk
bun add -d @cloudflare/workers-types
  • Install @swirls/looms and effect only at the versions @swirls/shuttle depends on, if at all, so there is one copy of each.
  • Put @cloudflare/workers-types in your tsconfig's types, for the bindings the engine's types name, and turn skipLibCheck on.
  • @swirls/shuttle/engine loads under Bun and Node as well, so your other code and your tests can import the ports and the headless API. @swirls/shuttle/engine/worker holds what only loads in a Worker.

Your Worker

Every session, pull request inbox and workspace is a Looms run, and every run lives in a Durable Object. The engine supplies the class; you subclass it to say who the host is. 

import type { ShuttleHost } from '@swirls/shuttle/engine'
import { EventFirehose, SessionSandbox, ShuttleRun } from '@swirls/shuttle/engine/worker'

export function host(env: Env): ShuttleHost {
  return { env, ports: { /* what your product decides; see Ports */ } }
}

export class LoomsRun extends ShuttleRun<Env> {
  protected override host(env: Env) {
    return host(env)
  }
}

export { EventFirehose }

// The sandbox is a Durable Object of its own and does not see the run's ports. Give it the
// same GitHub access as your `git` port, or export SessionSandbox as it is.
export class Sandbox extends SessionSandbox<Env> {
  protected override environment(env: Env) {
    return { ...env, GIT_ACCESS: myGitAccess(env) }
  }
}

Then bind the three classes under the names the engine looks for:

{
  "compatibility_flags": ["nodejs_compat"],
  "durable_objects": {
    "bindings": [
      { "name": "LOOMS_RUN", "class_name": "LoomsRun" },
      { "name": "SANDBOX", "class_name": "Sandbox" },
      { "name": "EVENT_FIREHOSE", "class_name": "EventFirehose" }
    ]
  },
  "migrations": [{ "tag": "v1", "new_sqlite_classes": ["LoomsRun", "Sandbox", "EventFirehose"] }],
  // Attachments and the media agents make. Optional.
  "r2_buckets": [{ "binding": "ASSETS", "bucket_name": "my-shuttle-assets" }]
}

Sandboxes run in memory until you choose otherwise (see Settings). For containers or Daytona, build the sandbox image from packages/sandbox/Dockerfile; it is not in the npm package.

Ports

A port is a small interface where your product makes a decision Shuttle would otherwise make itself. Every one is optional: leave it out and Shuttle does what it does standalone.

Port Decides Left out
identity Who a request acts for: a person, or an organization through a service. Nobody, so every API request is refused.
sessionStart Whether a session may start: a person's, an automatic review, or yours. Every start is allowed.
credentials Whose credential an agent turn runs on, the API keys you hold for them, and the model key for Shuttle's own agent loop. The person it works for, on their own vendor sign-in.
approvals How long a pull request proposal waits before a decision is refused. Forever.
git GitHub installation tokens, and a person's own token. Shuttle's own GitHub App, from env.
people Who is in an organization, which sharing a session is checked against. Nobody, so sessions are shared with no one.
previews Where preview hostname keys are kept. Sessions have no previews. 
export function host(env: Env): ShuttleHost {
  return {
    env,
    ports: {
      identity: ticketIdentity(env.TICKET_SECRET),
      sessionStart: {
        admit: async ({ orgId }) =>
          (await sessionsLeft(env, orgId)) > 0
            ? { allowed: true }
            : { allowed: false, reason: 'Your plan has no sessions left this month.' },
      },
      credentials: {
        // Every turn runs on the organization's own keys, and its model calls are billed to it.
        ownerOf: ({ orgId }) => (orgId === null ? null : { kind: 'organization', orgId }),
        apiKeys: async ({ orgId }) => orgApiKeys(env, orgId),
        modelKey: async ({ orgId }) => orgOpenRouterKey(env, orgId),
      },
      approvals: { expiresAfterMs: () => 7 * 24 * 60 * 60_000 },
      git: myGitAccess(env),
      people: { members: async (orgId) => memberIds(env, orgId) },
    },
  }
}
  • A turn never runs on another person's credential. A person's vendor sign-in stays in Shuttle's own encrypted store and only goes into that person's turns; no port can read it or supply one. What a port adds is API keys.
  • sessionStart is asked once per session. A start you repeat with the same idempotency key is the same session and is not asked again, so a port that counts starts counts each session once.
  • A decision made after approvals says a proposal expired is refused, and the agent is told so. Nothing wakes the session when the time passes.

Who is asking

The identity port looks at a request and says who it acts for, or null. Everything after that (who owns a session, which runs a request may open) is worked out from its answer. There are three ready ways to answer:

Port For
personIdentity(resolve) Your own sign-in. resolve turns a request into a person (user id, org id, role, name, email) or null.
serviceIdentity({ token, service }) Your backend calling over HTTP: a shared secret as a bearer token, and who it acts for in x-shuttle-org and, for a person, x-shuttle-user.
firstIdentity(...ports) The first of several ports that knows the request.

A port of your own is one function. This one takes a short-lived ticket your app signs for the person looking at a session, which is how a page on another origin is usually signed in: 

import { firstIdentity, serviceIdentity, type IdentityPort } from '@swirls/shuttle/engine'

const ticketIdentity = (secret: string): IdentityPort => ({
  async resolve(request) {
    const ticket = await verifyTicket(request.headers.get('authorization'), secret)

    return ticket === null
      ? null
      : {
          kind: 'person',
          actor: { userId: ticket.userId, orgId: ticket.orgId, role: 'member', name: ticket.name, email: '' },
        }
  },
})

const identity = firstIdentity(
  ticketIdentity(env.TICKET_SECRET),
  serviceIdentity({ token: env.SERVICE_TOKEN, service: 'acme-app' }),
)

An organization acting through a service owns nothing it starts: its sessions are open to the whole organization. A person's sessions are private to them until they share them.

Serving the API

serveShuttle answers the routes of the modules you mount, behind your identity port and the check of who may open which run. For any other path it answers null, so it sits in front of your own routes. 

import { serveShuttle } from '@swirls/shuttle/engine'
import { shuttleApiModules } from '@swirls/shuttle/engine/worker'

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const shuttle = serveShuttle(host(env), { modules: shuttleApiModules })

    return (await shuttle(request, ctx)) ?? myOwnRoutes(request, env)
  },
}
Module Serves Needs
runsApi A run's log, live, and the signals a browser may send it. /runs/:id/… A Worker
sessionApi A session, its playbook and its sandbox's files. /sessions/…, /playbook
assetsApi Attachments and the media agents make. /sessions/:id/assets The ASSETS bucket
terminalApi A session's terminal. /sessions/:id/sandbox/terminal A container sandbox
firehoseApi The organization's stream of what its public sessions do. /firehose
  • shuttleApiModules is all of them. portableApiModules, from @swirls/shuttle/engine, is all but runsApi, for code that loads outside a Worker. Every page that shows a session reads its run's log, so mount runsApi with whatever else you mount.
  • A request with nobody behind it is refused with 401, and one for a run its person may not open with 404, before any module sees it.
  • GET /capabilities says which modules are mounted, and the parts leave out what is not: mount sessionApi and runsApi alone and a page shows the conversation and the workspace, with no terminal and no media.

Under a path of your own

If your Worker has a /runs or /sessions of its own, mount Shuttle under a path with basePath, and give the parts the same path in baseUrl. 

const shuttle = serveShuttle(host(env), { modules: shuttleApiModules, basePath: '/shuttle' })

// On the page:
const host = createShuttleHost({ baseUrl: 'https://engine.example.com/shuttle' })

It then answers every path under /shuttle and null for the rest, and takes /shuttle off before a module sees the path, so /shuttle/capabilities and /shuttle/runs/:id/grant work too. A path under it that no module claims gets a 404 that a page on a listed origin can read.

A module of your own

A module is a plain object: a name for /capabilities, the paths it claims, and a handler that gets the request with the person already known. A tab kind of yours that says needs: ['designs'] appears once this module is mounted. 

import type { ApiModule } from '@swirls/shuttle/engine'

const designsApi: ApiModule = {
  name: 'designs',
  claims: (pathname) => pathname.startsWith('/designs/'),
  handle: async ({ request, actor, env }) => Response.json(await designsFor(env, actor.orgId, request)),
}

serveShuttle(host(env), { modules: [...shuttleApiModules, designsApi] })

Pages on another origin

A page on the Worker's own origin needs nothing more. When the page is somewhere else (your app on app.example.com, the engine on engine.example.com), give serveShuttle two more options: 

serveShuttle(host(env), {
  modules: shuttleApiModules,
  origins: ['https://app.example.com'],
  grantSecret: env.SHUTTLE_GRANT_SECRET, // at least 32 random characters
})
  • origins lists the pages that embed Shuttle. Answers to them carry the headers a browser needs to read them, preflights included.
  • grantSecret lets a page read a run's live log over a WebSocket, which cannot carry a sign-in. Someone who may open the run asks POST /runs/:id/grant for a short-lived read grant, and the log accepts it in place of a sign-in. The parts do this by themselves when the backend is on another origin. grantTtlMs sets how long a grant lasts (five minutes by default).

Headless sessions

Your backend can start a session with no interface at all: a brief, some repositories, and who it is for. It reports where the session stands, and takes answers to the questions its agents ask. 

import { answerHeadlessQuestion, headlessOutcome, startHeadlessSession } from '@swirls/shuttle/engine'

const acting = { kind: 'organization', orgId, service: 'acme-app' } as const

const { runId } = await startHeadlessSession(host(env), {
  acting,
  brief: 'Fix the flaky checkout test',
  repositories: [{ installationId, fullName: 'acme/shop', defaultBranch: 'main', private: true }],
  metadata: { ticket: 'SHOP-142' },
  idempotencyKey: 'shop-142',
})

const outcome = await headlessOutcome(host(env), runId)
// { state: 'working' }
// { state: 'completed', pullRequests: [{ repo, number, url, draft }] }
// { state: 'blocked', question: { approvalId, title, description, kind, expiresAt }, pullRequests }
// { state: 'failed', error, pullRequests }

if (outcome.state === 'blocked' && outcome.question.approvalId !== null) {
  await answerHeadlessQuestion(host(env), runId, outcome.question.approvalId, { text: 'Use Postgres' }, acting)
}
  • harness picks the agent that works the session (claude-code, codex, …), so an organization paying with its own API key gets the vendor that key is for. Left out, it is the deployment's default.
  • The same idempotencyKey returns the same session and changes nothing on it. A key that names someone else's session is refused.
  • question.kind says how to answer: an agent's question takes { text } (or null for the agent's own judgment); a pull request proposal or a drafted review (publish-pull-request, submit-review) takes { decision: 'approve' | 'reject' }. An answer of the wrong shape, or for a question that is not open, is refused with HeadlessRequestError and decides nothing.
  • headlessOutcome answers for any run id, so check that the session is the caller's before you pass its answer on. headlessSessions(host) gives the three calls bound to one host.
  • These calls reach runs through env.LOOMS_RUN, so they run in your Worker or anywhere else that holds the binding.

End to end

The usual arrangement for a product that puts sessions in its own pages: the engine runs in a Worker beside your app, your backend starts sessions, and your page shows them with the parts, signed in with a ticket your app signs.

1. The Worker: sessions, and the API under /shuttle

import { firstIdentity, serveShuttle, sessionApi, serviceIdentity, type ShuttleHost } from '@swirls/shuttle/engine'
import { runsApi } from '@swirls/shuttle/engine/worker'

const host = (env: Env): ShuttleHost => ({
  env,
  ports: {
    identity: firstIdentity(
      ticketIdentity(env.TICKET_SECRET), // pages
      serviceIdentity({ token: env.SERVICE_TOKEN, service: 'acme-app' }), // your backend
    ),
    credentials: orgCredentials(env),
    git: myGitAccess(env),
  },
})

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const shuttle = serveShuttle(host(env), {
      modules: [sessionApi, runsApi],
      basePath: '/shuttle',
      origins: [env.APP_ORIGIN],
      grantSecret: env.SHUTTLE_GRANT_SECRET,
    })

    return (await shuttle(request, ctx)) ?? myOwnRoutes(request, env)
  },
}

2. Your backend: start a session, sign a ticket

// A route of your own in the same Worker, or headlessSessions(host) behind serviceIdentity.
const { runId } = await startHeadlessSession(host(env), {
  acting: { kind: 'person', actor: { userId, orgId, role: 'member', name, email } },
  brief,
  repositories,
  idempotencyKey: workItemId,
})

return Response.json({ runId, ticket: await signTicket({ userId, orgId, name }, env.TICKET_SECRET) })

3. Your page: show it

const host = createShuttleHost({
  baseUrl: 'https://engine.example.com/shuttle',
  headers: () => ({ authorization: `Bearer ${latestTicket()}` }),
})

const identity = { tenant: sessionTenant({ user: me, orgId }), listPeople: async () => [] }

<Shuttle.Provider host={host} router={router} identity={identity}>
  <Suspense>
    <Shuttle.Session id={runId} readOnly={!mayDrive}>
      <Shuttle.SessionHeader />
      <Shuttle.Conversation />
      <Shuttle.Composer />
      <Shuttle.Artifacts />
    </Shuttle.Session>
  </Suspense>
</Shuttle.Provider>

Renew the ticket before it runs out and have headers read the newest one; the session stays connected across renewals. sessionTenant comes from @swirls/shuttle/api; see Who is signed in.

Settings

The engine reads these from env. All are optional.

Setting What it does
SHUTTLE_WORKSPACE_MODE Where sandboxes run: memory (the default), container (Cloudflare) or daytona, with DAYTONA_API_KEY and DAYTONA_SNAPSHOT.
OPENROUTER_API_KEY The model key for Shuttle's own agent loop, when credentials.modelKey gives none. LOOMS_MODEL picks the model.
SHUTTLE_CREDENTIALS_KEY Encrypts the vendor sign-ins people store with Shuttle.
GITHUB_APP_ID, GITHUB_APP_PRIVATE_KEY Shuttle's own GitHub App, when there is no git port.
ASSETS The R2 bucket for attachments and media. Needed by assetsApi.
SHUTTLE_PREVIEW_HOST The hostname sandbox previews are served under, with the previews port.

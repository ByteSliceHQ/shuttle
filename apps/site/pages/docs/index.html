@swirls/shuttle

Embed Shuttle

Shuttle runs coding agent sessions: agents that work in a sandbox on your repositories, talk to you while they do, and open pull requests when they are done. Everything Shuttle's own app is made of is published, so another product can put those sessions inside its own pages, on its own backend, under its own sign-in.

Build your own ADE Host the engine @swirls/shuttle on npm

Three ways in

There are two halves: the parts, React components that show a session, and the engine, which runs sessions and serves the API the parts talk to. Take one or both.

The parts Your own layout around Shuttle's conversation, composer and artifacts, pointed at a Shuttle backend you already run. Frontend only The parts and the engine Sessions inside your product: your Worker runs them, your sign-in decides who is asking, your organization's keys pay for them. Frontend and backend The engine alone Start a session from a brief and some repositories, follow it to a pull request or a question, and answer it. No interface at all. Backend only

How it fits together

A page of yours holds the parts. They reach the backend over HTTP for reads and writes, and over a WebSocket for the session's live log. The backend is a Cloudflare Worker: the engine answers Shuttle's routes beside your own, and every session is a Durable Object that the engine supplies and you bind.

Install

One package, with an entry point for each layer.

bun add @swirls/shuttle
Import What it is
@swirls/shuttle/react The Shuttle parts, useSession() and createShuttleHost
@swirls/shuttle/react/ui The plain controls the parts are drawn with
@swirls/shuttle/react/theme.css Tokens and styles, imported after Tailwind
@swirls/shuttle/engine Host ports, serveShuttle and the API modules that load anywhere, headless sessions
@swirls/shuttle/engine/worker The Durable Objects a Worker binds, and runsApi, which only loads in a Worker
@swirls/shuttle/api The backend's HTTP API as a zod contract
@swirls/shuttle/core/workspace The workspace run's events and schemas
@swirls/shuttle/core/pulls The pulls run's events and schemas

A page that uses only the parts also needs React 19, TanStack Query 5 and Tailwind CSS 4. A Worker that runs the engine also installs ai, @cloudflare/sandbox and @daytona/sdk, which the parts never load. Host the engine has the details.

The whole thing, briefly

A Worker that runs Shuttle's sessions and serves their API under your own sign-in, and a page that shows one. Each half has a page of its own with the rest.

worker.ts

import { serveShuttle, type ShuttleHost } from '@swirls/shuttle/engine'
import { EventFirehose, SessionSandbox, ShuttleRun, shuttleApiModules } from '@swirls/shuttle/engine/worker'

const host = (env: Env): ShuttleHost => ({ env, ports: { identity: myIdentity(env) } })

export class LoomsRun extends ShuttleRun<Env> {
  protected override host(env: Env) {
    return host(env)
  }
}

export { EventFirehose, SessionSandbox }

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const shuttle = serveShuttle(host(env), { modules: shuttleApiModules })

    return (await shuttle(request, ctx)) ?? myOwnRoutes(request, env)
  },
}

session-page.tsx

import { createShuttleHost, Shuttle } from '@swirls/shuttle/react'

const host = createShuttleHost({ baseUrl: 'https://engine.example.com' })

export function SessionPage({ runId }: { runId: string }) {
  return (
    <Shuttle.Provider host={host} router={router} identity={identity}>
      <Suspense>
        <Shuttle.Session id={runId}>
          <Shuttle.Conversation />
          <Shuttle.Composer />
          <Shuttle.Artifacts />
        </Shuttle.Session>
      </Suspense>
    </Shuttle.Provider>
  )
}

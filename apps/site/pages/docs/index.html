@swirls/shuttle

Build your own ADE

Shuttle's interface is a set of React parts: a session, its conversation, the composer, the artifacts pane, the agents. Shuttle's own web and desktop apps are only one way of putting them together. Install the parts and put them together your way, with your own layout, your own parts beside ours, and your own kinds of tab.

View on GitHub @swirls/shuttle on npm The example

Install

One package, with an entry point for each layer.

bun add @swirls/shuttle @tanstack/react-query
Import What it is
@swirls/shuttle/react The Shuttle parts, useSession() and createShuttleHost
@swirls/shuttle/react/ui The plain controls the parts are drawn with
@swirls/shuttle/react/theme.css Tokens and styles, imported after Tailwind
@swirls/shuttle/api The backend's HTTP API as a zod contract
@swirls/shuttle/core/workspace The workspace run's events and schemas
@swirls/shuttle/core/pulls The pulls run's events and schemas

How it fits together

There are three layers. A host says how to reach the backend. The provider gives every part the host, your router and who is signed in. A session follows one session's run, folds its events once, and hands the result to every part inside it. The parts take no session props of their own, so you can arrange them however you like.

A first ADE

A conversation on the left, artifacts on the right, and no sidebar. This is all it takes once you have a backend to point at. 

import { createShuttleHost, Shuttle } from '@swirls/shuttle/react'

const host = createShuttleHost({ baseUrl: 'https://shuttle.example.com' })

export function MyADE({ sessionId }: { sessionId: string }) {
  return (
    <Shuttle.Provider host={host} router={router} identity={identity}>
      <Shuttle.Session id={sessionId}>
        <div className="grid h-dvh grid-cols-[1fr_420px] grid-rows-[auto_1fr]">
          <div className="col-span-2">
            <Shuttle.SessionHeader />
          </div>
          <main className="flex min-h-0 flex-col">
            <Shuttle.Conversation />
            <Shuttle.Composer />
          </main>
          <aside className="min-h-0 border-l">
            <Shuttle.Artifacts />
          </aside>
        </div>
        <Shuttle.Palette />
      </Shuttle.Session>
    </Shuttle.Provider>
  )
}

The provider expects a TanStack QueryClientProvider above it. Where the router and identity come from is covered in Fitting it into your app.

The parts

Part What it does
Shuttle.Provider Gives the parts the host, the router and who is signed in. Everything goes inside it.
Shuttle.Session Follows one session and gives it to the parts inside.
Shuttle.SessionHeader The session's title, status and controls.
Shuttle.Conversation The conversation with the agents, with turns streaming in as they are written.
Shuttle.Composer Where you write to the agents and steer them while they work.
Shuttle.Agents The session's agents as a tree of threads.
Shuttle.Artifacts The tabbed pane: files, changes, previews, terminals, and any kinds you add.
Shuttle.Events The run's raw event history.
Shuttle.Palette The command palette.
Shuttle.SessionLayout Shuttle's own arrangement of all of the above, for when you want the whole thing.
Shuttle.Shell The frame with folders and sessions down the side. Leave it out if your app has its own navigation.

You can start with Shuttle.SessionLayout and take it apart later, or start from the individual parts. Both work with nothing above them but the provider.

A part of your own

useSession() returns what the stock parts read: the title, the status, the conversation, the agents and the raw events. A component of yours that calls it can sit anywhere inside <Shuttle.Session>. 

import { useSession } from '@swirls/shuttle/react'

function StatusStrip() {
  const { status, identities, events } = useSession()

  return (
    <div className="border-b px-3 py-1 text-[11px] text-muted-foreground">
      {status} · {identities.size} agents · {events.length} events
    </div>
  )
}

Your own kinds of tab

The artifacts pane knows only the kinds of tab it is given. Add yours to Shuttle's and it shows up in the pane's menu and in the command palette like any other. 

import { defaultArtifactTypes, type ArtifactType } from '@swirls/shuttle/react'

const designs: ArtifactType = {
  kind: 'acme:designs',
  label: 'Designs',
  icon: <PenTool size={14} />,
  launcher: { keywords: 'figma mockups', starter: true },
  render: ({ tab, runId }) => <DesignBoard runId={runId} id={tab.target} />,
}

<Shuttle.Session id={sessionId} artifactTypes={[...defaultArtifactTypes, designs]}>
  • Name your kinds namespace:name, as in acme:designs, so they never collide with Shuttle's.
  • The backend keeps your tabs, with their title and target, without knowing what they show. What target means (an id, a URL, a path) is up to you.
  • single: true keeps one tab of the kind at most. Leave launcher out to open tabs only from your own code, such as a link in a message.
  • Someone who opens the session in an app that doesn't have your kind sees a note saying so, not an empty pane.

Fitting it into your app

The parts never assume where they are running. Your app gives them three things.

The host

createShuttleHost is called once, outside React, so your route loaders and the parts share one client and one cache. baseUrl points at the backend (left out, it is the page's own origin), and fetch lets you add your own credentials to every request. 

const host = createShuttleHost({
  baseUrl: 'https://shuttle.example.com',
  fetch: (input, init) => fetch(input, { ...init, credentials: 'include' }),
})

The router

Parts link to destinations, never to paths: { page: 'session', sessionId }, { page: 'home' } and so on. Your router says where each one is in your app. Here is the whole adapter for an app with a single page: 

const router: ShuttleRouter = {
  Link: ({ to, ...rest }) => (
    <a {...rest} href={to.page === 'session' ? `?session=${to.sessionId}` : '#'} />
  ),
  navigate: () => {},
  location: { page: 'session', sessionId },
}

Who is signed in

identity is the signed-in person and their organization, as the backend returns them, and a way to list the people in it for names and sharing. 

const tenant = useQuery({ queryKey: ['me'], queryFn: () => host.client.tenant.me() }).data
const identity = tenant ? { tenant, listPeople: async () => [] } : null

Styles

The parts are styled with Tailwind CSS 4. Import the theme after Tailwind and it tells Tailwind to read the package's files, so there is nothing to add to your config. 

@import 'tailwindcss';
@import '@swirls/shuttle/react/theme.css';

What it needs

  • A Shuttle backend to talk to. It is the Worker in apps/worker, which runs on your own Cloudflare account, or locally with bun run dev.
  • React 19, TanStack Query 5 and Tailwind CSS 4.
  • A bundler such as Vite.
